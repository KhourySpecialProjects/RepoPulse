So what?

Four things change the week you start using it.

Dashboards are easy to build and easy to ignore. These are the questions RepoPulse is meant to answer, and the reason it exists at all.

01

You find the struggling team in week 3, not at the demo.

Recency and commit frequency move long before a deadline does. A repository that turns amber on Tuesday is a five-minute conversation on Wednesday, instead of a post-mortem at the end of term.

02

You can say who actually contributed.

Distribution scores how evenly the work is spread across a team, and alias merging means a student who commits from a laptop, a lab machine and the GitHub web editor still counts as one person. The dashboard tells you how many repositories are running on a single contributor.

03

One dashboard instead of thirty tabs.

A collection holds the whole cohort. Every repository is one click from its commits, its people and your notes — and one more click from GitHub or a local VS Code window when you want to read the code itself.

04

Evidence, not impressions.

Every score traces back to commits in a clone RepoPulse keeps, scored the same way each week. Every AI overview is stored with the model and timestamp behind it, so a summary is always something you can check rather than something you have to trust.

A normal check-in

  • Open thirty repositories one at a time
  • Skim the commit list and guess at momentum
  • Ask the room "how's it going?" and hear "fine"

Help

What is RepoPulse?

A local-first dashboard for monitoring student project repositories. It clones each repository, reads the full git history, scores six health signals, and puts the results — along with contributor analytics, AI overviews and your notes — in one place.

Getting started

  1. Sign in, then create a collection for your course or your cohort.
  2. Paste the GitHub URLs of your teams' repositories into it and sync. Each one is cloned and its full history read.
  3. Health scores and the workspace pulse appear once the first sync finishes. Open any repository from there for its commits, its contributors and your notes.

Do I need a GitHub token?

No. Cloning and analysis use git directly, so there is no API rate limit to work around and nothing to authorize. AI Overviews are the one part that calls out to a model provider, and Settings is where you choose which model and what it is asked to look for.

Controlling the tour

The chapter names along the bottom jump straight to a section. Click into the tour first and Space pauses or resumes it, while the arrow keys step through. It starts over on its own half a minute after the sign-off, stops while it is scrolled out of view, and stays still if your system is set to reduce motion.
